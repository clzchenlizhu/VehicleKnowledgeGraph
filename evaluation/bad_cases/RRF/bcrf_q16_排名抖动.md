# q16 输入测量值要求：答案块排名两次运行间抖动（HyDE 随机性）

## 测试问题
使用万用表时对输入测量值有何要求？

## 预期正确结果
- 答案片段：`请勿将输入的测量值超出其所允许的量程范围`
- 所在文档：万用表RS-12的使用 / `## 安全手册1_1` 块

## 实际召回表现
- 纯向量检索：正确答案排名第 **4** 位
- 混合检索（向量+假设问题 RRF）：**第 3 位（本次导出）/ 第 7 位（正式评测那次）**，两次运行不一致
- 差异说明：混合检索对这题**方向不稳定**——同一份测试集、同一次实验，两次跑结果在 3~7 之间跳。

## 根因分析
1. 正确块 `## 安全手册1_1` 前面堆了大量 `## 安全标识 11_x` 的图像 caption（"MAX最高量程""勿接500V"），这些噪声块和查询"量程/输入"字面很近。
2. HyDE 每次生成的假设段落措辞不同（LLM 有随机性），对这些图像噪声块的抬升程度忽大忽小，导致正确块在 3~7 之间抖动。
3. 本质：**在噪声块本就很强的题上，HyDE 的随机性直接传递成了排名波动**，让结果不可复现。

## 优化建议
- 给 HyDE 生成做缓存/固定种子，或对同一 query 多次生成取多数，降低单次随机性。
- 真正该做的是清理 `## 安全标识` 图像 caption 这类噪声块，让正确块稳定在前三。
- 结论：排名抖动说明 HyDE 带来的"提升"不可靠，不能作为上线依据。
